# 維護手冊

系統大部分時間不需要人照顧。這份清單列出**自動會做的事**、**人要定期做的事**，以及**出問題時怎麼辦**。

## 自動進行（不用管）

| 項目 | 怎麼運作 | 出問題時 |
|---|---|---|
| 防止資料庫休眠 | GitHub 每 3 天自動連一次資料庫和網站（`.github/workflows/keepalive.yml`） | 連不上時 GitHub 會**寄信給 repo 擁有者**，信件標題含「保活與健康檢查」 |
| 備份提醒 | 超過 60 天沒備份，管理員登入後首頁會出現提醒 | — |
| 練習提醒 | 每晚 20:00 在 DC 發「明天的行程」（設定好 DC 通知後才會運作） | — |

> GitHub 有個規則：repo **連續 60 天沒有任何更新**，排程會被自動停用。為了避免這件事，排程會在 repo 超過 30 天沒更新時，自動留一筆「自動保活」的空紀錄（不會新增任何檔案），所以平常不用管。萬一還是收到停用通知，到 repo 的 **Actions → 保活與健康檢查 → Enable workflow** 重新打開即可。

## 定期要做

### 每學期
- [ ] **開學**：設定 → 新增學期並設為目前學期。
- [ ] **開學**：成員頁調整幹部、組長、新生身分組；離團或畢業的人改成「停用」（紀錄會保留）。
- [ ] **開學**：絲竹頁更新絲竹名單。
- [ ] **期中、期末**：設定 → 匯出備份，三個檔案存到社團雲端硬碟。
- [ ] **期末**：曲目頁把不再演奏的曲子設為「封存」。

### 每年（換屆）
- [ ] 把「管理員」交給下一任（先加新的、再移除自己；系統不允許移除最後一位管理員）。
- [ ] 依 `HANDOVER.md` 交接帳號：GitHub、Supabase、Discord App、Google Cloud。
- [ ] 確認收「保活與健康檢查」失敗通知信的人是現任管理員（GitHub repo 擁有者）。

### 偶爾看一下
- [ ] Supabase 後台首頁的用量：資料庫（上限 500 MB）、檔案空間（上限 1 GB，主要是樂譜）。用到 80% 時，刪掉舊樂譜或壓縮 PDF。
- [ ] Discord webhook：如果有人刪掉或重建 DC 頻道，webhook 會失效，要到設定頁重新貼上。

## 出問題時

| 狀況 | 原因 | 怎麼辦 |
|---|---|---|
| 網站打開一直轉圈、或顯示「載入失敗」 | 資料庫休眠 | Supabase 後台 → 專案 → **Restore project**，約 2 分鐘恢復，資料不會不見 |
| 收到 GitHub「保活與健康檢查」失敗的信 | 同上，或 Supabase 帳號／專案異常 | 先照上一列處理；還是不行就看信裡的錯誤訊息 |
| 用 Discord 登入跳出一串程式碼 | Supabase 的 Discord 登入被關掉或設定跑掉 | Authentication → Sign In / Providers → Discord，確認開關打開並按 Save |
| 同一個人變成兩個帳號 | 用 Email 和 Discord 各註冊一次 | 刪掉多的那個，請本人在「我的設定」按「連結 Discord」 |
| 有人忘記密碼 | 免費方案沒有寄信功能 | Supabase → Authentication → Users 刪掉該帳號，請他重新註冊，再核准一次 |
| 改了網站但看到的還是舊版 | 瀏覽器快取 | 按 Ctrl+Shift+R（手機：關掉分頁重開） |
| 資料被誤刪 | — | 用最近一次備份的 .json 還原（需要懂程式的人協助，備份檔裡每個表格的資料都完整保留） |

## 給接手的開發者
- 修改流程：改程式 → `npm test`（要全部通過）→ 本機 `python3 -m http.server` 開 `?demo` 檢查 → 推上 `main`，約 1 分鐘後生效。
- 改資料庫結構時，`supabase/schema.sql` 要能重複執行；先在 Supabase 執行完，再推網站。
- 開發紀錄看 `HANDOFF.md`。
